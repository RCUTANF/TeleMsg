## 关键决策点

### 1. 为什么使用 WebSocket 而不是轮询？

✅ **优点**:
- 实时性强 (延迟 < 500ms)
- 服务器资源消耗低
- 双向通信
- 适合即时通讯场景

❌ **轮询缺点**:
- 延迟高 (取决于轮询间隔)
- 服务器负载大
- 带宽浪费

### 2. 为什么在后端发送通知而不是前端直接发送？

✅ **后端发送的优点**:
- 统一的消息路由
- 更好的安全控制
- 便于日志和审计
- 支持离线消息推送 (未来扩展)

### 3. 为什么使用独立的 IncomingCallDialog 组件？

✅ **组件化的优点**:
- 关注点分离
- 代码复用
- 易于测试
- 易于维护和扩展

## 性能优化点

1. **WebSocket 连接复用**: 所有实时通信共用一个 WebSocket 连接
2. **状态管理优化**: 使用 React hooks 避免不必要的重渲染
3. **消息格式精简**: 只传递必要的数据
4. **错误处理**: 完善的异常捕获和日志记录

## 安全考虑

1. **JWT 认证**: 所有 API 调用需要有效的 JWT token
2. **WebSocket 认证**: 连接时验证 token
3. **用户权限**: 只能向联系人发起通话
4. **输入验证**: 后端验证所有请求参数
